# P0 数据可行性报告：Pasal.id 作为中国出海场景的印尼法规数据底座

> **版本**：v1.0 | **测试日期**：2026-08-27 | **执行**：Kimi + 子代理
> **测试方法**：50 个中国出海企业真实合规问题 × Pasal.id 公开网页实测（搜索页 SSR 抓取 + 法规正文页验证），约 110 次请求，0 错误中断
> **原始数据**：`p0_test/results.csv`（50 行逐题结果）、`p0_test/raw_notes.md`（过程观察）、`p0_test/raw/`（100 个原始 HTML 存档）

---

## 1. 结论（TL;DR）

**Pasal.id 可以作为 LexNusa 的数据底座，但只在「高层级法规原文 + 状态 + 修订链」这一层。** 它的站内搜索很弱（召回约一半）、部长级法规缺失——这两个缺口恰好是 LexNusa 自建层的机会与必须补的课。

> 对 PM 评估报告 §2.1 的裁决：**方案 A（API 消费）验证可行**，但需满足三个配套条件（§4），且规模化商用需与 Pasal.id 达成量级安排。

## 2. 实测结果总览

### 2.1 搜索召回（50 题）

| 结果 | 数量 | 说明 |
| :--- | :--- | :--- |
| hit（期望法规进 top-5） | 23 | 多为"法规类型+名称"式查询（如 "undang-undang cipta kerja"） |
| partial（命中可替代/更新法规） | 3 | 如 THR 题命中 PP 28/2024 替代 Permenaker 6/2016 |
| miss | 24 | 业务词查询大量漏召，top-5 常被无关旧法占据 |

### 2.2 正文验证（46/50 通过）

所有期望的 UU/PP/Perpres 正文页真实存在、条文可 grep 验证。4 个例外均不构成否决项：

- UU 40/2007 公司法**缺 Pasal 142 文本**（解散清算条款缺口，疑"合并现行文本"展示问题）
- UU 3/2020 矿业法为修订法结构（Pasal I/II），实体条文须跳母法 UU 4/2009
- PMK 213/2016、PMK 48/2020 **不在库**（部长级缺口，见 §3.2）

### 2.3 意外收获：状态徽章可直接机读

正文页顶部状态徽章带稳定 CSS 类（`bg-status-berlaku/diubah/dicabut`），可程序化提取。实测抓到**反常识真相**：PP 5/2021（RBA 营业许可，很多中文攻略还当现行法引用）已被标 **Dicabut（已废止）**；UU 25/2007、UU 40/2007 均标 **Diubah**（被创造就业法修订）。**这正是 LexNusa "修订脉络追溯"卖点的数据基础，已验证可用。**

## 3. 三个关键缺口

### 3.1 搜索召回率约一半 → LexNusa 必须自建检索层（这反而是好消息）

Pasal.id 搜索是字面关键词匹配：无语义理解、印尼语新旧拼写（iktikad/itikad）导致漏召、业务词（"modal minimum PMA"）搜不到对应法。

**产品含义**：我们本来就要做中文/语义检索层（bge-m3 向量），实测证明这一层不是锦上添花而是**必需品**。数据底座只负责"原文 + 状态 + 修订链"，检索和中文映射完全由 LexNusa 自建——差异化定位进一步坐实。

### 3.2 部长级法规（PMK/Permenaker/PER）收录薄弱 → 需第二数据源

- PMK 213/2016（转让定价）、PMK 48/2020（数字服务 VAT）多种 slug 变体探测均不存在；
- 税务总局 PER 层级完全无命中；
- 库内 permen 类多为 2025–2026 新法规，历史部长级法规覆盖弱。

**而这是中国出海企业税务/劳工实操最需要的层级。** 候选补充源：peraturan.go.id 官方 PDF 自建、Hukumonline（商业库，需授权）、jdih.kemenkeu.go.id。建议列入 P1 任务，不阻塞 MVP。

### 3.3 数据质量校验层必不可少

- **伪 404 陷阱**：不存在的 slug 也返回 HTTP 200（72KB 通用页），判存在性必须看正文关键词或页面体积（真实页 400KB+）；
- 个别正文有条文缺口（UU 40/2007 Pasal 142）；
- 修订法/母法结构需要链接跳转逻辑。

凡入库数据必须过"正文体积 + 关键词 + 状态徽章"三重校验。

## 4. 方案 A 的三个配套条件（修订版数据架构）

```
┌─────────────────────────────────────────────┐
│ LexNusa 自建层（核心价值）                    │
│  · 中文映射层：问题→法规 slug 直连表          │
│  · 检索层：bge-m3 向量 + 关键词混合           │
│  · 中文解读/摘要/场景化标注                   │
│  · 企业私有知识（Obsidian 混合查询）          │
├─────────────────────────────────────────────┤
│ Pasal.id 消费层（API/MCP，需 token + 署名）   │
│  · 高层级法规原文（UU/PP/Perpres/Perppu）     │
│  · 修订状态徽章 + 修订链关系                  │
│  · 24-48h 增量更新                           │
├─────────────────────────────────────────────┤
│ 补充数据源（P1 补齐）                         │
│  · 部长级法规（PMK/Permenaker/PER）           │
└─────────────────────────────────────────────┘
```

1. **slug 直连映射层**：不依赖 Pasal.id 站内搜索，自建"核心法规清单 → slug"映射（首批公司/劳工/税务约 100~300 部）；
2. **部长级数据第二来源**：P1 补齐；
3. **三重校验**：体积 + 关键词 + 状态徽章，凡入库必验。

## 5. 商业化红线（更新认知）

- Pasal.id API 速率限制：search 60 次/分、360 次/小时（免费 token 档）。**MVP 用户量可用，规模化必须走其"高量级商用洽谈"通道**（其官网明示 "Hubungi kami untuk akses volume tinggi"）。
- AGPL-3.0 + 禁止整体再分发的约束不变：我们只消费 API 响应做展示层，不镜像其数据库，架构上保持"查询时拉取 + 短期缓存"，避免落成自有全量副本。
